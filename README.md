# Инструкция по сборке внешней компоненты 1С для воспроизведения звука

## Назначение

В репозитории находятся исходники внешней компоненты 1С для воспроизведения звука уведомления, а также инструменты для сборки браузерного адаптера.

Ниже приведен полный порядок сборки и подготовки пакета для загрузки в общий макет конфигурации УФА **`АРБИС_AddNotification`**.

---

## Требования к окружению

Перед началом сборки необходимо подготовить окружение.

### Необходимое ПО

- **Visual Studio**
- **NSIS** — обязателен для сборки адаптеров для браузеров

> Для сборки браузерных адаптеров NSIS должен быть установлен заранее.  
> Также для всех этапов сборки требуется установленная Visual Studio.

### Настройка версии Visual Studio в `build.cmd`

В `build.cmd`-файлах в начале обычно указаны строки:

```cmd
SET VS_VER=18
SET VS_YEAR=2026
SET VS_TOOLSET=v145
```

Эти значения **нужно установить в соответствии с вашей версией Visual Studio**.

То есть перед сборкой необходимо проверить, что:

- `VS_VER` соответствует установленной версии Visual Studio;
- `VS_YEAR` соответствует году версии Visual Studio;
- `VS_TOOLSET` соответствует установленному toolset.

> Если оставить значения, не соответствующие фактически установленной Visual Studio, сборка может завершиться с ошибками.

---

## Общая структура

В репозитории используются две основные части:

1. **Сборка динамических библиотек** — здесь собираются нативные библиотеки для разных платформ и архитектур:
   - `dll`
   - `dylib`
   - `so`

2. **Сборка адаптеров для браузеров** — здесь собирается браузерный адаптер, необходимый для работы компоненты вне тонкого клиента.

---

## 1. Сборка динамических библиотек

### Где находятся основные файлы

В папке `example/NativeApi` находятся ключевые исходники:

- **`Notification.h`** — содержит звук уведомления, зашитый в виде hex-последовательности.
- **`AddInNative.cpp`** — содержит основную логику работы компоненты, включая логику проигрывания звука.

### Сборка

1. Перейдите в папку `example`.
2. Проверьте настройки Visual Studio в `build.cmd`.
3. Убедитесь, что все исходники актуальны.
4. Запустите скрипт:

```cmd
build.cmd
```

### Что делает `build.cmd`

Скрипт собирает библиотеки для следующих архитектур Windows:

- **32-bit**
- **64-bit**
- **ARM**

После сборки создается папка **`pkg`**, в которой находятся:

- собранные библиотеки;
- **манифест**.

### Что содержит манифест

Манифест описывает:

- для какой **операционной системы** предназначена компонента;
- для какой **архитектуры** она предназначена;
- какую именно библиотеку нужно использовать в каждом случае.

### Результат сборки

Итогом является архив:

```text
win.pkg.zip
```

Этот архив можно напрямую загрузить в общий макет конфигурации УФА:

```text
АРБИС_AddNotification
```

### Важно

Если загрузить только этот архив, то компонента будет работать **только в тонком клиенте**.

Для работы через браузер необходимо дополнительно собрать **адаптер для браузера**.

---

## 2. Сборка адаптера для браузера

### Подготовка

1. Перейдите в папку:

```text
Сборка адаптеров для браузеров
```

2. Убедитесь, что:
   - установлен **NSIS**;
   - параметры Visual Studio в `build.cmd` соответствуют вашей установленной версии.

3. Внутри папки найдите каталог:

```text
NativeAPI
```

4. Скопируйте в него ранее собранные библиотеки.

### Требования к именам файлов

Файлы нужно назвать **строго** следующим образом:

- `AddIn32.dll`
- `AddIn64.dll`

> Это обязательное условие. При других именах сборка или дальнейшая работа могут быть некорректными.

---

## 3. Обновление версии адаптера

Перед новой сборкой необходимо открыть файл:

```text
Сборка адаптеров для браузеров/settings.cmake
```

И **увеличить версию компоненты**.

### Зачем это нужно

Если версию не поднять, платформа может продолжить использовать уже установленную старую версию компоненты и не предложит пользователю установить новую.

---

## 4. Сборка браузерного адаптера

1. Перейдите в папку:

```text
Сборка адаптеров для браузеров/project
```

2. При необходимости проверьте параметры Visual Studio в `build.cmd` / `win_build.cmd`.
3. Запустите скрипт:

```cmd
win_build.cmd
```

### Результат

После завершения сборки перейдите в папку:

```text
build
```

В ней будет сформирован архив:

```text
win.pkg.zip
```

---

## 5. Загрузка в конфигурацию

Полученный архив `win.pkg.zip` нужно загрузить в общий макет конфигурации УФА:

```text
АРБИС_AddNotification
```

После этого компонента будет готова к использованию в нужном режиме работы.

---

## Краткая схема процесса

### Сборка основной компоненты

```text
example/NativeApi/Notification.h   -> звук уведомления в hex
example/NativeApi/AddInNative.cpp  -> логика компоненты и проигрывания
example/build.cmd                  -> сборка библиотек
example/pkg/win.pkg.zip            -> пакет для 1С
```

### Сборка браузерного адаптера

```text
Сборка адаптеров для браузеров/NativeAPI/AddIn32.dll
Сборка адаптеров для браузеров/NativeAPI/AddIn64.dll
Сборка адаптеров для браузеров/settings.cmake   -> повышение версии
Сборка адаптеров для браузеров/project/win_build.cmd
Сборка адаптеров для браузеров/build/win.pkg.zip
```

---

## Полный порядок действий

1. Установить **Visual Studio**.
2. Установить **NSIS**.
3. Проверить в `build.cmd`-файлах параметры:
   - `SET VS_VER=...`
   - `SET VS_YEAR=...`
   - `SET VS_TOOLSET=...`
4. Привести эти значения в соответствие со своей версией Visual Studio.
5. Собрать нативные библиотеки через `example/build.cmd`.
6. Получить архив `win.pkg.zip` в папке `pkg`.
7. Помнить, что этого архива достаточно только для **тонкого клиента**.
8. Для браузера перейти в папку **«Сборка адаптеров для браузеров»**.
9. Скопировать собранные библиотеки в папку `NativeAPI`.
10. Переименовать библиотеки в:
    - `AddIn32.dll`
    - `AddIn64.dll`
11. Открыть `settings.cmake` и увеличить версию.
12. Запустить `project/win_build.cmd`.
13. Забрать готовый `win.pkg.zip` из папки `build`.
14. Загрузить архив в общий макет **`АРБИС_AddNotification`**.

---

## Примечания

- `Notification.h` отвечает за встроенный звук уведомления.
- `AddInNative.cpp` отвечает за поведение компоненты и воспроизведение звука.
- Обновление версии в `settings.cmake` обязательно для корректного обновления компоненты у пользователей.
- Для полноценной работы в браузере одной только сборки нативной библиотеки недостаточно — обязательно нужен браузерный адаптер.
- Для успешной сборки необходимо, чтобы настройки Visual Studio в `build.cmd` соответствовали реальной установленной версии среды и toolset.
